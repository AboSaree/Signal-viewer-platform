Medical Signal Viewer
Program Flow & Architecture

ECG · EEG · WFDB · Multi-Lead · Real-Time Canvas Renderer
01 / Overview

What This Program Does

This is a single-file web application (everything in one index.html) that lets a user upload a medical signal recording (ECG or EEG in WFDB format, or a simple CSV), view its waveforms in real-time animated canvases, and run several signal-analysis visualizations — including a scatter plot, polar plots, and an XOR periodicity detector. It also displays an AI diagnosis panel if the backend returns one.

It talks to a Django REST backend running on http://127.0.0.1:8000/api for parsing WFDB files. CSV files are parsed entirely in the browser without any server call.

Key idea: The frontend holds all the signal data in memory after upload. Everything you see — the scrolling waveforms, polar plots, scatter plot — is drawn every animation frame using the HTML5 Canvas 2D API, with no chart library at all.

03 / Core Services

SignalService & AnimationService

These two services are the backbone shared by every view in the app.

📦

SignalService

A tiny key-value store with event subscription. Holds all loaded signal data plus metadata (sample rate, channel count, window width, playback speed, status). Any code can call ss.on('windowWidth', fn) to react to changes — similar to a mini Redux.

⏱

AnimationService

Wraps requestAnimationFrame into a simple subscriber list. It increments a tick counter t on every frame and calls every registered callback. Views use this tick as a clock to compute the scrolling window position.

// SignalService — get and set state ss.set('windowWidth', 1000); // fires all listeners for 'windowWidth' ss.on('windowWidth', v => channelView.anchorAndResize()); // AnimationService — register a per-frame draw callback animService.add(t => channelView._draw(t));
04 / Program Flow

Step-by-Step User Journey

01

Page Load → App Bootstrap

When the DOM is ready, new App(document.getElementById('app')) fires. The App constructor calls _buildDOM() (writes all HTML via innerHTML), _bindEvents() (attaches file drop, slider, and button listeners), and as.start() (starts the RAF loop). At this point the screen shows only the upload drop-zone.

02

User Drops / Selects Files

_handleFiles() inspects the file list. If a .hea file is present → WFDB path. If a .csv is found → CSV path. Otherwise an error banner is shown. The two paths are:

🌐

WFDB Path

All files are bundled into a FormData and POSTed to /api/upload-view/ via XHR. The Django backend parses the WFDB record and returns JSON with channels, metadata, and optionally an AI diagnosis object.

📄

CSV Path

The file is read with FileReader entirely in the browser. Rows are split, parsed as floats, and shaped into the same JSON structure the server would return — then fed directly to _loadFromServerData().

03

Data Loaded → State & UI Update

_loadFromServerData(data) is called with the parsed signal. It pushes all values into SignalService (signalData, numChannels, fs, sigNames, windowWidth …), updates the metadata bar (record name, Hz, duration), sets the period slider bounds, shows the mode-choice card, and — if the server returned an ai object — calls _renderAI() to populate the AI diagnosis panel.

04

User Picks Display Mode

Two buttons appear: Separate Windows or Single Window.

  • Separate: _activateSeparate() creates one ChannelView per channel. Each gets its own canvas, play/pause, amplitude zoom, and inline color style button.
  • Single: _activateSingle() creates one SingleWindowView that renders all channels stacked on a single canvas with per-channel mini sub-axes, plus shows the global channel customization panel.

After the choice, the window-width, speed controls, and all analysis sections become visible.

05

Real-Time Rendering Loop

From this point the AnimationService ticks every frame (~60 fps). Every view's _draw(t) callback fires. The tick t combined with each view's windowStart and the playback speed computes which slice of signal data to render — creating the scrolling waveform effect. The user can drag the canvas to pan, scroll to advance, and use play/pause and amplitude buttons.

05 / View Classes

Every Canvas View Explained

Class Purpose Key Mechanics Interaction
ChannelView One scrolling waveform per ECG/EEG lead Uses _leftEdge(t) = (windowStart + t × speed) % signalLength to decide which samples to draw. Draw.signal() maps sample index → pixel x, amplitude → pixel y. Drag to pan, scroll to advance, play/pause, AMP±, color picker, SNAP saves PNG
SingleWindowView All leads on one shared canvas, stacked in equal-height bands Each channel occupies a vertical "band" of height totalH / numChannels. Draw.miniSubAxis() draws per-channel min/max tick labels within each band. Same as ChannelView but controls apply globally; per-channel color in customization panel
ScatterView Cross-plot of two leads (X vs Y scatter) Each data point (xData[i], yData[i]) is projected to canvas coordinates. Points are colored by time (HSL hue shift). Zoom/pan transform the view window without recomputing data. Scroll to zoom, drag to pan, SNAP, RESET VIEW
PolarView Single lead in polar coordinates — r = amplitude, θ = time within period For each sample: r = (value − min)/(max − min) × maxRadius; θ = 2π × (sampleIndex mod period) / period. Drawn with a thick glow pass + fine line pass. Scroll to zoom, drag to pan, SNAP, RESET
PolarRatioView Polar plot where r = |Lead A| / |Lead B| — reveals relative amplitude patterns Ratio array is precomputed in constructor. Otherwise identical drawing logic to PolarView. Scroll to zoom, drag to pan, SNAP, RESET
XorView Periodicity heatmap — detects positions in the cycle that vary across repetitions Signal is sliced into n/windowWidth chunks. For each x-position within a chunk, standard deviation across all chunks is computed. High σ → anomalous (red); low σ → periodic (blue/black). Rendered as a pixel color buffer. SNAP only; static (not animated)
DigitalXorView Companion to XorView: dot plot of the mean signal at positions where chunks disagreed Uses max-min range across chunks vs tolerance gate. Dots appear only at disagreeing positions, plotted at their mean value. Shows where anomalies sit in amplitude space. SNAP only; static
06 / Drawing

The Draw Object (Shared Canvas Helpers)

Instead of each class reimplementing canvas drawing, a static Draw object holds reusable helper functions called by every view:

▦

Draw.grid()

Draws faint cyan grid lines (12 vertical, 6 horizontal) and a dashed center baseline.

〰

Draw.signal()

Iterates pixels left-to-right, computes the sample index from window position, and draws the waveform as a glow + fine-line double stroke.

|

Draw.periodMarkers()

Draws dashed vertical lines at every window-width boundary so you can visually see where each period starts.

⟷

Draw.axes()

Draws the full X (sample index) and Y (mV) axes with tick marks — used in the full-axis Separate and ScatterView modes.

⊟

Draw.miniSubAxis()

Draws a tiny colored channel-name badge + min/max tick lines within a band — used in Single Window mode only.

08 / Customization

Global Color & Thickness State

Channel colors and line widths are managed through three module-level globals, not inside any class. This lets all views (ChannelView, SingleWindowView, analysis plots) stay in sync automatically:

// Defaults — 12 colors cycling const CHANNEL_COLORS = ['#63b3ed', '#68d391', '#fc8181', …]; // Override maps — sparse (only channels the user changed) const channelColorOverrides = {}; // idx → hex string const channelThickOverrides = {}; // idx → px number const onChannelColorChange = []; // subscriber callbacks // Helpers used by every draw call getChannelColor(idx) → override || default palette getChannelThick(idx) → override || 1.5 setChannelColor(idx, color) → stores + fires all subscribers

When the user picks a new color via the color swatch in either the inline STYLE button (Separate mode) or the global Customization panel (Single mode), setChannelColor() fires all registered onChannelColorChange listeners so every UI element (swatch, label, canvas border) updates simultaneously.

10 / Signal Analysis

XOR Periodicity Analysis — How It Works

This is the most algorithmically interesting part of the frontend. Given a window width W, the signal is conceptually divided into N/W chunks. For each position x within a chunk (0 to W−1), values from all chunks at that position are collected. The standard deviation across those values is computed:

// For every x-pixel position within the window: posInWindow = floor((x / canvasWidth) × W) values = [ data[0×W + pos], data[1×W + pos], data[2×W + pos], … ] σ = stdDev(values) // If σ > threshold → anomalous (the signal differs at this phase) // If σ ≤ threshold → periodic (signal is consistent at this phase) color = σ=0 → dark (periodic) σ>0 → blue→amber→red (increasingly anomalous)
Think of it like stacking transparencies of each heartbeat on top of each other. Wherever they all line up (periodic) you see black. Wherever they differ (arrhythmia, noise, artifact) you see color. The DigitalXorView is a companion that plots only the mean value at each "disagreeing" position as dots on a waveform axis.

12 / Design Notes

Notable Design Decisions

No chart library

All rendering is raw Canvas 2D API. This gives full control over rendering performance for large signals (tens of thousands of samples) and custom effects like the glow-double-stroke technique.

Single file

The entire app — HTML, CSS, and ~1700 lines of JS — lives in one index.html. This makes deployment trivial; just open it in a browser (with the Django server running for WFDB files).

Reactive state via SignalService

Instead of passing props everywhere, all views subscribe to SignalService. This decouples views from each other — adding a new analysis view only requires subscribing to the relevant state keys.

RAF tick as clock

The playback position is computed from the integer tick t times the speed scalar, not from Date.now(). This keeps animation perfectly frame-rate-synced and makes pause/resume trivial to implement.

XOR = periodicity by definition

The XOR analysis doesn't use a signal processing library. It directly measures cross-chunk variance at each phase position — a conceptually simple but effective heuristic for detecting heartbeat irregularity.

Mode separation

Separate vs Single Window modes share the same underlying data and controls, but use completely different rendering classes. This avoids complex branching inside draw calls.
